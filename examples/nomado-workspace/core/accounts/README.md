# Реестр кабинетов

Каждый кабинет — свой каталог: `accounts/<slug>/`. Внутри всё, что зависит от
конкретного кабинета: ставки комиссий, ассортимент, поставщики, условия работы.

Добавить кабинет:

```bash
cp -r core/accounts/_template core/accounts/<slug>
$EDITOR core/accounts/<slug>/profile.md
```

| slug | Чей | Тип | Статус |
|---|---|---|---|
| `own` | свой | собственная торговля | |
| `<slug>` | `<клиент>` | клиентский | активен / пауза / завершён |

## Правило, которое важнее остальных

**Никогда не смешивай данные разных кабинетов в одном ответе.** Цифры одного
клиента не должны попасть в разговор про другого — ни в сравнении, ни в примере,
ни «для контекста». Если вопрос неоднозначен, спроси, о каком кабинете речь.

Свой кабинет (`own`) — такое же ограничение: клиенту не показываются ваши закупочные
цены, а вам в отчёте по клиенту не подмешиваются свои.

## Если клиент получает доступ к боту

Тогда ему нужен **отдельный бот и отдельный workspace**, а не общий с доступом
к части файлов. Плагин изолирует по процессу: один агент = один бот = один
workspace = один allowlist. Разграничение «внутри одного бота по ролям» надёжным
не будет — агент видит все файлы, до которых дотягивается.

## Клиентские данные и git

Каталог `accounts/` живёт **только на сервере** и в репозиторий не коммитится.
Здесь лежит чужая коммерческая информация: закупочные цены, обороты, поставщики.
В репозитории — только `_template/` с пустыми полями.
