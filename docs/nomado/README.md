## 1. Что меняется, а что нет

Номадо — это не сайт и не один репозиторий, а **связка «два VPS + агенты в Telegram»**.
Переориентация бьёт только по верхнему слою — по предметной области. Инфраструктура,
на которой всё стоит, к домену бизнеса безразлична.

| Слой | Travel-торговля (сейчас) | Маркетплейсы (цель) | Переделка |
|---|---|---|---|
| Хостинг | 2 × VPS Start (Финляндия), 1289 ₽/мес | без изменений | нет |
| Транспорт | Telegram → Claude Code (`dashi-channel`) | без изменений | нет |
| Память агента | `core/hot/recent.md` + `verbose-*.jsonl` | без изменений | нет |
| Safety / redact | редактор секретов + HTML-валидатор | без изменений | нет |
| **Воркспейс агента** | travel-промпт, travel-данные | промпт и данные по маркетплейсам | **полная замена** |
| **Слой данных** | ‹уточнить: что за travel-данные› | товары, цены, поставки, реклама, отзывы | **новый** |
| **Внешние API** | ‹уточнить: GDS / партнёрки?› | WB Seller API, Ozon Seller API | **новый** |
| Домен | `nomadotravel.com` | ‹уточнить: оставляем или переезжаем› | решение за вами |

Вывод, который стоит зафиксировать до начала работы: **платформу переписывать не нужно.**
Плагин `dashi-plugin-claude-code` — предметно-нейтральный транспорт. Переориентация Номадо =
новый воркспейс агента + новый слой данных + коннекторы к маркетплейсам. Это недели работы,
а не месяцы, и старый travel-воркспейс можно просто оставить рядом, не удаляя.

## 2. Роль агента после переориентации

Агент маркетплейсов — не «чат-бот про Wildberries». Он полезен ровно там, где у селлера
уходит время на рутину с числами и текстом:

1. **Юнит-экономика до закупки.** Считает маржу по товару с учётом комиссии, логистики,
   хранения, эквайринга, налога и процента выкупа. Отвечает на «заходить или нет» цифрой,
   а не мнением. Ядро всего остального — см. `unit-economics.md` в шаблоне воркспейса.
2. **Разбор ниши.** По категории и запросу — вилка цен, кто в топе, насколько плотно,
   какая нужна оборачиваемость, чтобы окупить вход.
3. **Карточки.** Заголовок, характеристики, описание под поиск маркетплейса; переписывание
   слабых карточек из текущего ассортимента.
4. **Ежедневная сводка.** Продажи, остатки, «что заканчивается», «что встало», аномалии по
   рекламным ставкам — приходит в Telegram сама, без запроса.
5. **Отзывы.** Черновики ответов на негатив, группировка жалоб в «что чинить в товаре».

Пункты 1–3 работают сразу и на ручных данных. Пункты 4–5 требуют Seller API-ключей.

## 3. Раскладка по двум серверам

Сейчас два одинаковых VPS, и по скриншоту не видно, чем они отличаются по нагрузке.
Разумное разделение, которое заодно оправдывает второй сервер:

**`lab.nomadotravel.com` — production**
- `nomado-market` — основной агент маркетплейсов в Telegram (systemd, автозапуск)
- travel-агент — если он ещё нужен, остаётся рядом на своём порту ‹уточнить: нужен ли›

**`quwawiyawe585` — данные и обкатка**
- ночные сборщики: остатки, продажи, позиции, ставки → в файлы воркспейса
- canary-агент для проверки изменений промпта до выката на prod
- бэкапы `core/` и `logs/` с lab

Если второй сервер после этого всё равно простаивает — его можно не продлевать 22.09
и сэкономить 1289 ₽/мес; но сборщики тогда переезжают на lab и конкурируют за память
с живой сессией Claude. Мой совет — оставить, разделение prod/staging окупается первым же
кривым промптом, который не уехал на боевого бота.

## 4. Слой данных

Агент читает и пишет обычные файлы в воркспейсе — никакой БД на старте не нужно:

```
~/.claude-lab/nomado-market/.claude/
├── CLAUDE.md                 # роль, правила, чего не делать
├── core/
│   ├── hot/recent.md         # память между сессиями (пишет плагин)
│   ├── unit-economics.md     # формула + ваши реальные ставки комиссий
│   ├── assortment.md         # текущие товары: закуп, цена, остаток
│   └── suppliers.md          # поставщики, сроки, минимальные партии
└── data/                     # выгрузки: sales-YYYY-MM-DD.csv, stocks-*.csv
```

Переход на SQLite имеет смысл, когда позиций станет больше ~200 или понадобится история
цен по дням. До этого файлы читаются агентом целиком и это дешевле во всех смыслах.

## 5. Этапы

| Этап | Что делаем | Результат |
|---|---|---|
| 0 | Поднять воркспейс `nomado-market` из шаблона | Бот в Telegram отвечает по маркетплейсам |
| 1 | Заполнить `unit-economics.md` реальными ставками | Считает маржу по вашим цифрам |
| 2 | Занести текущий ассортимент в `assortment.md` | Отвечает про ваш товар, а не абстрактный |
| 3 | Ключи WB/Ozon Seller API → ночные сборщики | Ежедневная сводка приходит сама |
| 4 | Решение по travel-контуру: оставить / архивировать | Один сервер освобождается или нет |

Этап 0 применяется одной командой — см. `scripts/nomado-workspace-init.sh`.

## 6. Допущения — поправьте, если мимо

- ‹уточнить› Маркетплейсы = **Wildberries + Ozon**, продажа собственного товара
  (не байер-услуги, не консалтинг для других селлеров). Если модель другая — меняется
  почти весь раздел 2.
- ‹уточнить› Travel-контур ещё живой и его нельзя просто снести.
- ‹уточнить› Домен `nomadotravel.com` остаётся, несмотря на смену профиля.
- ‹уточнить› Юрлицо/налоговый режим для расчёта маржи — предполагаю УСН 6%.

Ставки комиссий, логистики и хранения **намеренно не проставлены**: они меняются по
категориям и по времени, и выдуманное число в расчёте маржи хуже, чем пустое поле.
В шаблоне под них стоят явные placeholder'ы.

## 7. Чего я не видел

Эта сессия работает в одноразовом контейнере: наружу открыт только HTTPS через прокси,
SSH-ключей нет, `nomadotravel.com` заблокирован егресс-прокси. Поэтому текущий код Номадо,
содержимое серверов и живой travel-контур я не смотрел — блюпринт опирается только на
устройство `dashi-plugin-claude-code` и на ваше описание.

Чтобы снять это ограничение, есть два пути: либо выложить код Номадо в репозиторий, к
которому у меня есть доступ, либо давать мне задачи через агента, который уже живёт на lab —
у него руки на самой машине есть.
